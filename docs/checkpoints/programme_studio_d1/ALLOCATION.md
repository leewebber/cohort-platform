## Smallest useful author workflow

1. Open a dedicated, local, non-production Stage 2 authoring preview containing only synthetic fixtures. Existing Studio/Apollo/Bali/Spartan review remains intact and read-only.
2. Choose a clearly labelled synthetic unpublished v1 package. Load its canonical YAML and immutable synthetic protocol-source bundle, compile through `PlanPackageCompiler`, then initialize transient editable fields only after a valid parse. Never initialize from generated Studio review JSON.
3. Edit programme metadata and the existing week/day schedule. Select session references from an explicit immutable fixture catalogue showing exact revision identity; titles are labels, never identity matching. Review a session's existing prescription alongside the schedule.
4. Add/remove/move required training slots within existing weeks/days, using explicit unique slot keys and explicit ordering. Confirm operations that remove/change authored references; do not regenerate keys from titles or silently repair dangling contracts. Only training/rest day placement is editable in this first slice. Existing optional semantics are preserved read-only.
5. Validate the entire candidate through the unchanged shared compiler, not only visible fields. Show path/code/actionable message. Produce no current-valid export or current-valid hash while invalid. Unsaved invalid input can remain in transient controls for correction.
6. Show a reviewable diff from the original YAML plus a semantic before/after review. Refresh the existing `ProgrammeReviewProjector.projectBundle` and Studio Coach Review / Athlete Preview / Quality Gate / Technical Integrity from the **exact exported YAML** and exact synthetic protocol bundle. Compile success is not coaching, publication or launch approval.
7. Explicitly export the valid YAML text through an Export/Copy YAML control. Recompile that exact text and require byte/hash equality with the reviewed result immediately before export. Any later edit invalidates the prior reviewed hash/export approval. Show the hash in Technical Integrity, not as the primary author task.
8. Reopen exported YAML through the same local intake and demonstrate the same authored meaning and package identity. Reset/cancel returns to original source; neither review nor closing the preview writes the original file.

Export generates canonical-source YAML, satisfying Stage 2's “writes or generates the same canonical representation” rule. A copied/exported file is the durable authored source; transient form state is a derived working projection. No persistent Studio document database, autosave, localStorage, parallel builder format, network resolver or new lifecycle is introduced. “Local unpublished copy” is a workspace status, not a new database lifecycle state. The existing operator import/publish path remains separate.

## YAML / compiler / hash contract

Add a Studio-local, pure **v1 source YAML writer**, using existing typed package vocabulary. No change to shared parser, validator, canonicaliser, schemas or hash algorithm is expected. Every canonical v1 field must be serializable, including fields the editor does not expose. Preserve complete typed values; refuse unsupported schemas/fields rather than drop them.

Output is human-readable YAML with documented stable key/collection order, safe string quoting (including numeric-like strings, booleans, colons, newlines and Unicode), UTF-8 and LF with one final newline. Existing canonical ordering/default normalization is reused without altering package content. Comments/formatting are not hash inputs and may normalize in the export; original YAML is retained untouched and the textual diff makes that visible. Semantic round-trip equality, not original whitespace equality, is required.

`compile(input)` → complete manifest → allowed field edits → YAML writer → `compile(export)` → existing canonical bytes/hash. Unedited v1 exports must equal the input's existing canonical bytes/hash. Changed supported meaning must cause only the intended semantic diff and its corresponding hash change. Re-export must be byte-identical; opening/re-exporting must be idempotent. v2 editor refusal must never strip a running document, downgrade schema or leak compiler-generated `execution_mapping_sha256` back into authored YAML. Existing v2 goldens and retained artifact verification continue unchanged.

Compilation validates declared package consistency, not live protocol publication/ownership. For synthetic review, a local resolver must establish exact fixture protocol/lineage/revision matching. Missing/mismatched/unsupported prescription sources are shown as failures; a syntactically valid package with an unresolved session cannot receive a successful complete author-review/export outcome. No hosted fallback is allowed.
