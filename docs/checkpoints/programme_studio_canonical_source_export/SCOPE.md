## Why this milestone

Programme Studio §§3/5 requires structured editors generating the existing Plan Package
and protocol authoring YAML. The current complete review contains exact sources, but
requires technical extraction from JSON before using canonical files in the existing
operator workflow. Deliver one explicit Download canonical sources action in the existing
export summary, after fresh joint validation. Authors can edit/save/explicitly select/
review, then retain actual canonical source files and the complete read-only review.

Smallest compatible assumption: download a deterministic uncompressed standard TAR archive,
containing the existing programme YAML, every declared session revision's exact Founder
YAML (including unused revisions/roots), a source index, explanatory README and unchanged
complete review JSON. Stable safe filenames use fixed lineage A/B plus revision number;
never user titles. No archive intake, editable restore, second store or new canonical schema.
Container/index are derived transport, never authority. No new dependency required.

Use current live or separately reopened receipt and existing consumption guards. Saving
private versions alone cannot include them; no draft or implicit selection. Failed/stale
review must not download. Explain read-only reopening, temporary workspace, synthetic
fixture limits, no publication/approval or historical provenance proof. A platform download
is a requested file transfer, not proof that the user retained it. Do not call this durable
editable authoring or Stage 2 closure.

## Acceptance

- Programme YAML compiles with unchanged canonical compiler; all exact session files
  independently compile against unchanged identity/profile policy and match the index.
- Deterministic bytes/order/filenames, valid standard TAR independently extracted with
  system tar/Python tarfile, UTF-8 fidelity and exact A R1 preservation.
- Include exactly all declared versions (unused too, both roots for B); exclude private
  saved versions/drafts. Same-title/same-number A/B stay distinct by full identity.
- Reopen unchanged review JSON through existing v1/v2 validator; live owners, selection,
  revision reservations unchanged. Tampering refusal and old transport remain intact.
- UI summary explains files and limitations; download only after current validation and
  final exact-byte consumption guard, including cross-owner/reset/disposal races.
- Test meaningful source-to-file-to-compiler/reopen outcomes and stale download boundaries;
  use prior valid compatibility evidence where unchanged, six safety groups for changed
  architecture surface, zero changed-file/new diagnostics versus fresh full analysis.
- Protect all compiler/schema/hash/resolver/allocator/source/profile/transport/published/
  golden code and all older checkouts. Normal main-only publication after gates.

No new lineage/profile/representation, real content, hosted mutation/publication,
production/athlete wiring, persistence service, migration or device distribution.
