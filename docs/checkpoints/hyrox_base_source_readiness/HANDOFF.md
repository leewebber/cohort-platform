## Practical independent tooling

From repository root:

```sh
dart run tool/programme_studio/check_source_readiness.dart
# Optional: an existing real registry ID, for example apollo-build-v2
```

The default reads the existing `hyrox-base` planned-family record and reports **absent
source**, **missing source/approval**, and downstream **not assessed**. It does not scan
personal files or silently substitute another programme. Existing registered source IDs
reuse ProgrammeReviewWorkspace/Projector and PlanPackageCompiler; source-text SHA-256,
compiler package hash, malformed/missing EX reference syntax (existing ExerciseId),
unavailable canonical definition versions, unsupported-prescription findings and blocked/
incomplete/human-required review are distinct. No parser for human approval is added.

A compiled package, filename, registry/lifecycle label, publication artifact or matching
hash never establishes documented founder approval. Even valid EX references remain
unresolved for authoritative definition versions; the tool does not accept definitions,
make row snapshots into versions, resolve names or create mappings. Identity resolution
still belongs to the accepted import/bridge boundary. See DECISION for the exact gap.

Exit **0** means a derived report was generated, even when source is absent; it is not a
readiness or approval pass. Unknown/fixture/pilot IDs refuse (65); unreadable registered
files refuse (66); extra arguments refuse (64). Generated JSON is a **report**, never an
editable/source transport or publication input. The command has no arbitrary-file intake
and no import, mutation, human-approval recording or persistence operation. A future Base
candidate needs an explicitly reviewed source registration/adapter before technical
projection; this task does not create one speculatively.

Existing movement rendering/unsupported findings are reused, not broadened. Empty body/
failed compile cannot yield an empty-list pass. No detected limitation still requires
human review and does not prove every timer/block/capture field. The report performs no
trusted import compatibility proof; canonical publication always remains not established.
Existing YAML, workspace/TAR, read-only transports, compiler/schema/hash semantics,
sources, SQL, dependencies, published artifacts, goldens and synthetic trust remain intact.
