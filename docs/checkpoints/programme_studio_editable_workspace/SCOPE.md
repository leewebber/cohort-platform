## Contract interpretation and design

Studio §§3/5 keeps canonical YAML authoritative. A versioned local JSON workspace file
is an explicit portable envelope of those canonical programme/frozen-session sources,
form draft inputs and local revision bookkeeping. It is not a second prescription
schema/store, publication payload, trusted history proof or cloud persistence service.
Use the existing two controllers/catalogues, compiler/profile policy, forms and projector.

Keep three distinct actions/products: canonical source download for compiler/tools;
complete review export for separate read-only inspection; Save editable workspace /
Open editable workspace for continuing local authoring. Never reinterpret review JSON
or source TAR as editable state. No browser autosave or cloud backup.

Store both owners' exact frozen bytes (private versions too), frozen parent edges,
high-water reservations/abandoned numbers, opened/standalone selections and active draft
identity/parent/form inputs; programme draft canonical source and admitted tuple set
carry explicit slot selections. Restore genuine newly owned entries by recompiling all
frozen sources against fixed profile/exercise versions; validate graph/no-op/identity
consistency and exact A R1. Existing shared allocator/schema/hash/writers unchanged.
Invalid scalar form values remain unvalidated drafts. Unsupported raw source text,
if retained as rejected input, stays opaque and never grants validation/freeze authority.

Candidate reconstruction is separate; no live mutation until explicit replacement
confirmation tied to current workspace state. Failure/cancel/staleness disposes the
candidate. Receipts, review successes, busy operations, rejected review packets, tabs,
focus, dialogs and clipboard state are excluded. Recompute reviews after opening.
Programme textual diff baseline resets to the fixed source seed; live edits persist.

Format v1: strict keys/types, duplicate-key rejection, fixed profile fingerprint,
bounded total UTF-8 size/depth/node/string counts, bounded revisions and reservation
high-water, fixed lineage identities and wrapper/templates. JSON index consistency
is not historical provenance or founder approval. No merge into existing owners.
Revision high-water is restored so abandoned identities cannot be reused in that
workspace; reopening an older saved copy intentionally creates an independent local
branch, without a global allocator, cross-file merge or external uniqueness promise.

## Acceptance

- Save/download/open/edit/save completes in Chrome with understandable dirty/save state.
- Both lineages, all private/admitted frozen versions, explicit slots, independent
  immutable bytes, abandoned numbers and active invalid drafts survive round trip.
- Root creation/cancel/failure rules and no-op descendant protections remain unchanged.
- Strict conflicting/duplicate/foreign/unsupported/oversized input refusal, without
  partial mutation. No serialized receipt authority or old review-as-editable intake.
- Candidate preview and explicit replace; cancellation/failure/stale completion cannot
  mutate current owners, selections or reservations. Save consumption handles races.
- Deterministic serialization of persistent state; no claim that a requested download
  proves retention. Existing standalone D1/D2, read-only transport and source downloads
  stay compatible. Focused regressions, six unchanged safety groups, fresh inherited
  full-analysis identity comparison and zero changed-file diagnostics; protect artifacts.

No broader source/profile/representation/schedule support, hosted mutation, real
publication, athlete-data change, migration, payment or device distribution. Broader
Stage 2/Sprint C and four genuine-record-dependent phone checks remain open.
