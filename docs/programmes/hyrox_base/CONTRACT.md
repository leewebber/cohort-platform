# Canonical source lowering and duration-choice contract

2026-10-24. Source-preserving local implementation, not hosted deployment or commercial
publication. The existing authoritative publication/event boundary is unchanged.

`PROGRESSION.json`, exact transfer/approval records and approved Base rules generate
48 independent complete main working sources, eight rest entries, readable coverage,
an all-category audit and an explicit candidate-definition register. Main prescription
completeness is separate from quantitative preparation and authoritative binding readiness.
No routine presentation change invents a prescription or a required actual-result field.

`CanonicalSessionSourceCompiler` takes canonical JSON source bytes, explicit exact
variant/version/digest pins, the established ExerciseKnowledgeRepository lookup and the
existing verified-publication authority port. No default fixtures, name lookup, catalogue
fallback, publication flag or matching untrusted hash supplies authority. Missing, draft,
wrong-version/digest or unverified definitions refuse before lowering. Local candidate
definitions remain unadmitted. Software fixtures test every source but certify no real
Base exercise. Unknown main working constructs/fields and contradictory interval steps refuse.

Lowering reuses SessionBlock, StrengthExercisePrescription, TimerConfiguration and the
existing runner. Additive fields retain RIR/rest ranges, per-side carry distance, timed
holds, after-pair rest and timed/full-rest stations. Existing JSON shape stays unchanged
when these fields are absent. Original source metadata is kept separately from human
prescription copy and actuals. Bound squat graph projection retains the established strict
5RM parameter shape plus exactly the approved 150–180 s rest range. Dedicated interval
source scopes remain closed; mixed finishers never acquire dedicated-row benchmark targets.
Existing timer aliases are normalized once at source compilation so save/reopen is exact.

The execution-plan persistence codec now retains exercise position, all execution-group
fields and block capture mode; these were previously lost on reopen. It also retains
complete source and frozen duration metadata. Typed range/source fields survive model and
prepared-plan serialization. The performance snapshot includes prescription metadata, not
new actual fields. A server-side record guard requires the exact frozen duration packet
through draft save, completion and actual-result correction; omitting/forging it refuses. Core and mixed finishers use existing completion/optional notes; ordinary
strength/endurance/interval capture stays unchanged. See CAPTURE_AND_PREPARATION.md.

Main easy/long duration windows are stored as `durationRangeSeconds`, with no default
chosen value. The programme launcher asks for a deliberate in-range main duration only
when a new canonical start needs one. Cancellation leaves no started occurrence. The
existing start store sends `p_duration_choices` to an additive three-argument RPC. A local
migration delegates to the established v3 owner/consent/source/session transaction, checks
all ranged blocks against retained physical source, and atomically inserts an immutable
FK-linked duration snapshot. Missing/out-of-range/foreign choices roll back the entire
start. Retry returns the original choice; withdrawal/replacement cannot rewrite it. The
public two-argument RPC delegates to this validation, and its prior body becomes a revoked
private helper. Original one-argument and v1/v2 behaviour are preserved. A malformed or
missing frozen choice refuses at the app boundary. Source ranges are not rewritten.

The selected duration and original range survive the existing prepared-plan and
started/performance snapshot paths. Restore compares original source, frozen choice and
bound prescription before accepting saved actuals. Timed EMOM stations change work/recovery
phase at the authored second while retaining the complete minute clock; rep stations have
no invented completion time. Full third-minute rest includes the final round. Dedicated
intervals/accelerations omit final recovery. Unspecified ramp/dynamic instructions stay
visible; no quantitative preparation is invented.

Two distinct local transports remain explicit:

- `REVIEW_EXPORT.json` retains the complete unbound review source, including policies,
  unresolved dependencies and approval provenance; it is not publication authority.
- `CompiledCanonicalSessionSource.exportSource()` retains exact canonical source bytes,
  SHA-256, exact resolved versions/provenance and the complete lowered model graph.
  Reopen recompiles against current authoritative inputs and requires exact graph equality;
  a supplied graph/hash never establishes authority or historical approval.

These are source JSON transports, not an expansion of the existing synthetic-only Studio
canonical TAR intake, and not a new publication service. A real producer must assign exact
physical protocol/revision/block identities and approve the final artifact through the
existing trusted boundary. No ID/version/event is fabricated to make compilation appear
ready. Local normalisation does not modify Plan Package v1/v2/v3 canonical hash meanings.
